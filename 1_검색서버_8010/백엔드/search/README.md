# DICE 뉴스 사건 검색

회원·서버 즐겨찾기 연결은 [API 명세 v0.2.163](accounts_api.md)을 참고한다. 별도 회원 DB 역할/DSN을 사용하며 기존 비로그인 검색과 프론트 화면은 유지한다.

기본 웹 화면은 React 19와 Tailwind CSS 4를 사용한다. 프로젝트 루트에서 `Push-Location 프론트엔드` → `npm.cmd run build` → `Pop-Location`으로 먼저 빌드한 뒤 아래 명령으로 백엔드를 시작한다. `프론트엔드/dist/index.html`이 있으면 `/`에서 화면을 제공하고, 없으면 서버 렌더 HTML을 제공한다. `/classic`에서는 서버 렌더 화면을, `/timeline`에서는 서버 렌더 타임라인을 제공한다. 개발 서버의 `/api` 프록시는 `127.0.0.1:8020`으로 연결된다.

**필수 키워드가 포함된 자연어 주제 검색**이다. 입력칸 두 개(필수 키워드 / 자연어 주제)와 검색 버튼 하나를 제공한다. 하나만 입력해도 되고, 둘 다 비면 모델·DB 검색을 하지 않는다.

기본 20개 사건(최대 50개)을 저장된 동아일보 우선 대표 기사로 접는다. 관련 기사 수·기간은 전체 묶음 기준이며 대표 기사는 검색 조건과 직접 일치하지 않을 수 있다. 펼치면 매칭 기사 상위 3건과 주제 문장이 있을 때 기사별 코사인 유사도를 보여준다. 묶음 없는 기사는 단독 사건이다.

검색 결과 위에 **월별 기사 수 · 주요 키워드** 패널 하나를 표시한다. 루트 `news_search_mockup.html`의 MonthlyStats처럼 위에는 SVG 막대, 아래에는 **월 | 기사 수 | 주요 키워드** 표를 배치한다. 2026-01부터 DB 전체 데이터의 최근 월까지 0건인 달도 표시한다. 주요 키워드는 **그 달에 평소(검색 기간 전체)보다 특히 많이 나온 키워드**다. `키워드(그 달 횟수, x배수)` 형식으로 배수는 소수 1자리까지 표시한다. 검색에 쓴 필수 키워드와 `engine.py` 상단 `KEYWORD_STOPWORDS`의 일반어(이날·지난·이번·관련·최근·오전·오후·올해·지난해·이후·당시·한편·이같이·오늘·내일·등)는 표시 후보에서 제외한다.

`/classic`의 통계는 인라인 SVG와 표로 표시한다. React 화면의 월별 막대는 화면 폭에 맞춰 줄바꿈되며, 월별 건수와 키워드는 접이식 표에서도 확인할 수 있다.

통계 집합은 사건 카드·대표 기사·매칭 상위 3건과 다르다.

- `kw`가 있으면 **모든 필수 키워드에 정확 일치하는 전체 기사**다. `q` 유무·유사도·임베딩 유무·사건 limit·상위 200건과 무관하고 상한이 없다.
- `kw` 없이 `q`만 있으면 **HNSW 후보 기사 집합(최대 200건)**이다. 전체 DB의 주제 일치 기사 수를 뜻하지 않는다.
- 같은 기사 집합에서 `share_m(k) = 그 달 k의 mention 합 / 그 달 전체 mention 합`, `share_all(k) = 집합 전체 기간 k의 mention 합 / 집합 전체 기간 전체 mention 합`, `lift = share_m / share_all`로 계산한다. **분모에는 필수 키워드·불용어도 포함**한다. 그 달 포함 기사 수가 3건 이상이고 `lift > 1`인 후보를 **`mention_m(k) × ln(lift)` 내림차순 → 키워드 `COLLATE "C"` 오름차순**으로 최대 4개 표시한다. 필수 키워드를 제외해도 기사 집합·월별 기사 수는 그대로다. 해당 월에 기사나 표시 가능한 후보가 없으면 키워드 목록은 비어 있고 표에는 `—`를 표시한다.

프로젝트 루트 PowerShell에서 실행한다. 기존 `백엔드/.venv`, 로컬 E5-base 캐시와 CUDA를 사용하며 패키지 설치·모델 다운로드는 하지 않는다. DB 설정은 기존 `load_bigkinds.connection_options`와 동일하게 `BIGKINDS_DSN` → `BIGKINDS_ENV_FILE` → `백엔드/.env` 순이며 접속값은 출력하지 않는다.

```powershell
# 키워드 교집합 안에서 자연어 주제 유사도순
& '백엔드/.venv/Scripts/python.exe' '백엔드/search/cli.py' --keywords '강선우,공천헌금' --q '재판 결과와 형량'
& '백엔드/.venv/Scripts/python.exe' '백엔드/search/cli.py' --kw '트럼프' --q '관세 인상 발표' --json
# 키워드만: 모델 불필요, 최신순
& '백엔드/.venv/Scripts/python.exe' '백엔드/search/cli.py' --keywords '러브버그'
# 주제만: HNSW 상위 후보, 유사도순
& '백엔드/.venv/Scripts/python.exe' '백엔드/search/cli.py' --q '노벨문학상 수상자 발표' --json
# JSON/stdin (PowerShell 파이프 UTF-8)
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
'{"keywords":["강선우","공천헌금"],"q":"재판 결과와 형량","limit":20}' | & '백엔드/.venv/Scripts/python.exe' '백엔드/search/cli.py' --json
# DB/모델 없는 자체 점검
& '백엔드/.venv/Scripts/python.exe' '백엔드/search/cli.py' --self-test
# 기본 8010. 운영 서버가 있으면 8020 사용, 종료 Ctrl+C
& '백엔드/.venv/Scripts/python.exe' '백엔드/search/app.py' --port 8020
```

웹은 `127.0.0.1`에만 바인딩하며 FastAPI·uvicorn을 사용한다. 인라인 CSS·HTML 이스케이프·HTTP/HTTPS 링크 제한·보안 헤더를 유지한다.

## 지인 공유 테스트(Cloudflare Quick Tunnel 예시: cloudflared tunnel --url http://127.0.0.1:8010)

환경변수는 앱 자체에서 처리하므로 다른 배포 방식에도 적용된다. 설치·다운로드는 수행하지 않으며 `cloudflared` 설치 여부는 사용자가 판단한다.

- `SEARCH_PASSWORD`: 값이 설정되면 JSON API와 서버 렌더 화면에 HTTP Basic 인증을 요구한다. React의 초기 HTML·JS·CSS·로고는 공개하며, API의 `401` 응답을 받으면 로그인 폼을 표시한다. 서버는 비밀번호만 `hmac.compare_digest`로 비교한다. 비밀번호는 출력·로그에 남기지 않는다.
- `SEARCH_PORT`: 기본 `8010`. 실행 인자 `--port`가 있으면 우선한다. 바인딩 주소는 항상 `127.0.0.1`이다. 운영 8010을 유지한 별도 검증에는 `SEARCH_PORT=8020`을 사용한다.
- 클라이언트별 60초 고정 창에서 20회까지 허용하고 21회부터 `429`와 `Retry-After`를 반환한다. 인증 실패·없는 경로도 포함하고, React 초기 HTML·정적 리소스의 정상 조회는 한도에서 제외한다. IP는 `CF-Connecting-IP` → `X-Forwarded-For` 첫 값 → 소켓 주소 순서다. `ponytail` 한계: 메모리·프로세스별 상태여서 재시작 시 초기화되고 여러 워커에 공유되지 않으며 창 경계에서 연속 요청이 가능하다. 전달 헤더는 신뢰하는 터널을 전제로 하므로 헤더 위조 방지는 제공하지 않는다.
- 성공·인증/입력/없는 경로 오류·요청 제한 응답에 `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`를 붙인다. 내부 예외·SQL은 오류 응답에 표시하지 않는다. `q` 200자, `kw` 전체 100자 초과 시 `400`을 반환한다.

PowerShell에서 비밀번호를 명령 이력에 직접 적지 않고 입력한 뒤 실행한다.

```powershell
$searchSecret = Read-Host '공유 테스트 비밀번호' -AsSecureString
$env:SEARCH_PASSWORD = [System.Net.NetworkCredential]::new('', $searchSecret).Password
$env:SEARCH_PORT = '8010'
& '백엔드/.venv/Scripts/python.exe' '백엔드/search/app.py'
# 별도 터미널에서 실행(이미 설치한 경우)
cloudflared tunnel --url http://127.0.0.1:8010
# 종료 후 앱을 실행했던 터미널에서 정리
Remove-Item Env:SEARCH_PASSWORD, Env:SEARCH_PORT -ErrorAction SilentlyContinue
```

JSON은 CLI `--json`, Python `search(...)`, HTTP `GET /api/search?kw=...&q=...`에서 같은 응답 형식을 사용한다. API에도 이전 mode 링크·입력 검증·읽기 전용 실행이 적용된다. 빈 API 검색은 모델·DB를 호출하지 않고 빈 통계를 반환한다.

- `GET /api/search?ask=...`는 질문 변환 결과와 실제 적용한 `params`, 검색 사건·기사, 월별 통계를 반환한다. `followups=1`을 붙이면 각 사건의 `followups`도 조회한다.
- `GET /api/timeline`은 검색과 같은 조건을 받아 `header`, 월별 흐름의 `months`, 날짜별 사건의 `items`, 요약 검사와 LLM 시간을 반환한다. 각 사건에서 대표 기사·동일 보도·후속 기사를 확인할 수 있다.
- `GET /api/publishers`는 기존 주요 언론사 목록과 기타 언론사(`__others__`)를 `{value, label}` 형식으로 반환한다.

```json
{
  "stats": {
    "basis": "필수 키워드 모두 일치한 전체 기사 · 주제(q)·임베딩 유무·결과 상한과 무관",
    "monthly": [
      {"month": "2026-01", "count": 0, "top_keywords": []},
      {"month": "2026-02", "count": 3, "top_keywords": [{"keyword": "재판", "mention_sum": 7, "article_count": 3, "lift": 1.56}]}
    ]
  },
  "timings": {"stats_ms": 12.3}
}
```

위 JSON은 필드 설명용 축약 예시다. 실제 응답은 기존 검색 결과·시간 필드와 DB 최근 월까지의 모든 월을 포함한다. `stats`는 `{basis, monthly:[{month,count,top_keywords:[{keyword,mention_sum,article_count,lift}]}]}` 형식이다. `mention_sum`은 그 달 언급 합, `article_count`는 그 달 해당 키워드를 포함한 기사 수, `lift`는 전체 기간 대비 그 달 비중의 배수다. 집합 크기는 월별 `count` 합으로 표시하며, 현재 2026년 데이터에서는 `keyword_candidate_count`(kw 있음) 또는 `candidate_count`(q만 있음)와 같다. 검색 조건 자체가 비어 있으면 `monthly`도 빈 목록이며, 조건은 있으나 일치 기사가 없으면 월별 0건·빈 `top_keywords`를 반환한다. 텍스트 CLI도 같은 월별 표를 출력한다.

- 결합 검색: <http://127.0.0.1:8020/?kw=강선우%2C공천헌금&q=재판%20결과와%20형량>
- 키워드만: <http://127.0.0.1:8020/?kw=러브버그>
- 주제만: <http://127.0.0.1:8020/?q=노벨문학상%20수상자%20발표>

URL은 `kw`, `q`를 사용한다. 이전 `mode=keyword&q=...`는 `kw`로, `mode=topic&q=...`는 주제 `q`로 처리한다. `kw`를 명시하면 두 입력이 우선한다. CLI/JSON의 이전 `mode=keyword/topic`도 호환한다. mode 없는 `q`는 이제 자연어 주제다.

화면 맨 위의 **질문**에 일상 문장을 입력하면 로컬 Ollama가 `{keywords, q}`로 바꾸고 바로 검색한다(`/?ask=...`, 질문 최대 500자). 변환 조건은 아래 **필수 키워드 / 자연어 주제** 칸에 표시된다. 이 칸을 고쳐 재검색하면 질문을 다시 변환하지 않는다. 변환 결과·제거된 키워드와 이유·LLM 시간(잠금 대기 포함)을 작게 표시한다. `GET /api/search?ask=...`의 JSON에는 `conversion`이 포함된다.

`keywords`는 핵심 명사·고유명사 최대 3개이며 공백·쉼표로 다시 나눈 뒤 일반어를 제거한다. 기존 `article_keywords.keyword` 인덱스를 이용한 `EXISTS`로 존재를 확인하고, 없으면 필수 조건에서 뺀다. 빈도 조회는 인덱스에서 최대 50,001건까지 읽으며 50,000건을 초과하는 단어는 필수 조건에서 빼고 `q`에 남긴다. 모두 빠지면 주제만 검색한다. `q`는 짧은 명사형 주제로 생성하도록 지시하며, 검색에는 기존 multilingual-e5-base(768차원)의 `query: ` 접두사·정규화 임베딩을 쓴다. 키워드 존재 확인은 개별 단어 기준이므로 여러 필수 키워드의 교집합이 비는 경우까지 방지하지는 않는다.

`/classic`의 **사건 타임라인 · 날짜순**은 검색 결과를 먼저 렌더한 뒤 `GET /timeline?kw=...&q=...&fragment=1`에서 HTML을 받아 삽입한다. JavaScript를 끈 경우 **타임라인 보기** 링크(`/timeline?kw=...&q=...`)에서 서버 렌더 페이지를 볼 수 있다. React는 동일한 타임라인을 `/api/timeline`에서 비동기로 받는다. 기존 Basic 인증·요청 제한·보안 헤더는 두 방식에 적용된다. 타임라인 호출은 60초 20회 한도 중 한 요청을 사용한다.

검색 상위 최대 8개 사건을 묶음의 `date_from` → `date_to` → 사건 ID 순으로 정렬한다. Ollama 입력은 사건별 날짜 범위·대표 제목·다른 매칭 제목 최대 3개·전체 묶음 언론사 목록·기사 수뿐이며 **기사 본문은 조회·저장하지 않는다**. 날짜는 사건 발생일을 추정한 값이 아니라 DB 묶음의 기사 발행 기간이다. JSON 스키마 `{headline, lead, items:[{event_index,date_label,title,summary}]}`로 응답을 제한하고, 항목 수를 입력 사건 수로 지정한다. 제목의 사실만 사용하며 추측·인과관계·숫자 창작·출처 생성을 금지한다. 작은 모델이 부인/인정의 주체를 바꾸거나 예정된 일을 완료로 단정하는 실제 오류가 있어 **제목을 원문 그대로 선택하는 추출형 요약**을 사용한다. 자유로운 문장 재서술은 표시하지 않는다.

서버는 잘못된 index·중복·빈 항목을 버리고 `event_index`로 원 사건에 연결한다. 표시 날짜는 LLM의 `date_label`을 사용하지 않고 서버 원 사건의 날짜 범위로 덮어쓴다. 출처 배지(`동아일보 +N` 등)의 언론사 수와 대표 기사 링크도 DB에서 붙인다. 소제목·설명에 해당 사건 입력 제목에 없는 숫자 토큰이 있으면 항목을 버린다. 남은 문구는 공백을 정규화해 원 제목 전체와 일치하는지 확인한다. 불일치 소제목은 해당 사건 대표 제목, 불일치 설명은 같은 사건의 다른 입력 제목(없으면 대표 제목)으로 대체한다. `extractive_fallback_count`는 설명을 대체한 항목 수다. headline은 전체 입력 제목 중 하나와 일치하지 않으면 검색 최상위 대표 제목으로, lead는 일치하지 않으면 방법 안내로 대체하며 `header_fallback:true`를 반환한다. 이를 통해 숫자뿐 아니라 주체·시제·확실성 변경을 막는다. 원 제목 자체의 정확성 및 사건 묶음 품질까지 보장하지는 않는다. 앞 3개 항목과 HTML `details`의 **펼쳐서 더보기**를 표시하며 하단에 `기사 제목만 근거로 로컬 AI(qwen3:4b)가 정리한 요약입니다. 원문을 확인하세요.`를 붙인다(모델 변경 시 모델명도 변경). 제목이 하나뿐인 사건은 소제목과 설명이 같을 수 있다.

검색 경로:

- 키워드만: `article_keywords.keyword` 정확 일치 기사 ID를 기존 SQL `INTERSECT`로 교차한다. `(keyword, mention_count)` 인덱스를 사용한다. 사건·매칭 기사는 최신 매칭 발행일 내림차순(동률은 사건/기사 ID 내림차순)이며 임베딩·가점이 없다.
- 주제만: HNSW 상위 200건(`ef_search=200`)의 근사 검색이다.
- 결합: 동일한 키워드 교집합 전체 ID를 먼저 구한 뒤 해당 임베딩만 기본키로 읽는다. `MATERIALIZED` CTE와 `LATERAL ... OFFSET 0`으로 범위를 확정한 후 `ORDER BY e.embedding <=> %s::vector, e.article_id DESC LIMIT 200`으로 정확 정렬한다. **HNSW를 사용하지 않는다.** 임베딩 없는 기사는 거리 평가에서 빠진다. 정확 거리 상위 200개 기사를 사건으로 접고 상위 20개 사건을 반환한다.
- 주제가 있으면 사건 점수는 후보 중 최고 코사인 유사도이며 동률은 사건 ID 내림차순이다. 보도량·키워드 가점이 없다. 반환 사건 통계·대표·매칭 상세는 일괄 조회한다.

통계는 **SQL 한 번**으로 계산한다. `matched AS MATERIALIZED` CTE로 집합을 확정하고 `dated AS MATERIALIZED`에서 기사별 월을 한 번 조회해 월별 건수·월×키워드 `GROUP BY`에 재사용한다. 모든 키워드의 언급 합과 포함 기사 수를 집계한 뒤 윈도 합으로 월별·키워드별·전체 기간 합을 구해 `lift`를 계산한다. 이후 후보 조건·제외어를 적용하고 점수로 `row_number()`를 매겨 `rank <= 4`를 월별 JSON에 담는다. 키워드가 있으면 같은 쿼리에서 교집합 전체 ID를 반환하고 검색 본 쿼리는 그 ID 배열을 재사용한다. 주제만 있으면 기존 HNSW 후보 ID를 전달한다. 날짜와 키워드는 `LATERAL ... OFFSET 0`과 기존 기사별 인덱스로 읽는다. 임시 테이블·영구 테이블·인덱스를 생성하지 않으며 검색 본 쿼리와 통계 쿼리는 **같은 REPEATABLE READ READ ONLY 트랜잭션**에서 실행한다.

트럼프 집계는 CLI·HTTP·별도 SQL 모두 약 1.3초였으며 부하·네트워크·데이터 증가에 따라 변동한다. CLI 모델 준비 23,878.0ms는 위 전체 시간에서 분리했다. 서버 시작 후 첫 트럼프 API 요청은 모델 준비 대기 포함 전체 27,067.8ms였고, 강선우·공천헌금 API는 전체 487.0ms였다. HTML·JSON 모두 200, 인증 없는 요청·틀린 비밀번호 401, 올바른 인증 200, 같은 IP의 첫 20회 200·21회 429, 긴 q/kw 400과 보안 헤더를 실제 8020에서 확인했다. 대체 `http.server`의 같은 보호 장치와 비밀번호 미설정 시 인증 없는 FastAPI도 확인했다. 테스트 서버는 종료했고 8010은 유지했다. 브라우저 육안 검증은 미완료다.

트럼프 집계는 CLI·HTTP에서 **1.5초 목표를 충족**했다. 별도 `EXPLAIN ANALYZE`는 1,519.016ms로 목표를 조금 넘었고, 부하·캐시·네트워크·데이터 증가에 따라 변동하므로 항상 1.5초 이내를 보장하지 않는다. 최적화 전 초기 월별 집계는 3,275.6ms였다. 세 조건 모두 2026-01~11의 11개월과 월별 상위 4개 언급 합·제외어·동률 순서·빈 집합을 독립 읽기 전용 SQL 및 Python 정렬로 검증했다. HTML·JSON HTTP 200 확인 후 8020 서버를 종료했고 운영 8010은 유지했다. CLI 모델 준비 26,665.0ms, HTTP 첫 주제 요청은 준비 대기 포함 28,145.0ms로 위 표에서 분리했다. 브라우저 육안 검증은 미완료다.

최신 JSON API 회귀 검사는 `백엔드`에서 `.venv/Scripts/python.exe -X utf8 -m pytest -p no:cacheprovider search`로 실행한다.

웹 서버 시작 시 모델 로드와 첫 CUDA 추론을 **백그라운드**에서 수행한다(FastAPI lifespan). 홈·키워드 검색은 준비 중에도 응답하고 주제 요청은 준비 완료 이벤트를 기다린다. 준비 후 첫 실제 주제 검색부터 모델을 재사용한다. 준비에는 약 25초가 걸리므로 시작 직후의 주제 요청은 남은 준비 시간만큼 대기한다. 준비 실패는 접속값 없는 오류로 안내하며 서버 재시작이 필요하다. CLI는 별도 프로세스여서 주제 검색에 모델 준비 시간이 포함된다.

`elapsed_ms`는 요청 대기·임베딩·접속·SQL·사건 접기를 포함한다. `timings`에는 `embedding_ms`, `connection_ms`, `candidates_ms`, `stats_ms`, `groups_ms`, `details_ms`가 있다. `stats_ms`는 통계 CTE 실행·결과 수신을 포함하며, 키워드 검색에서는 재사용할 교집합 확정 시간도 포함한다. `candidates_ms`는 해당 ID의 검색·정렬 시간이다. 모델 준비 후 실측과 준비 중 요청은 구분한다.

DB 연결은 기본 읽기 전용이며 `REPEATABLE READ READ ONLY`·`transaction_read_only=on`을 확인한다. SELECT·SHOW·트랜잭션 로컬 설정만 실행하고 **DB 쓰기·스키마 변경·인덱스 생성은 하지 않는다**. SQL당 제한 시간은 10초다. 제목 trgm GIN이 없어 제목 전체 스캔은 하지 않으며 추출 키워드 형태 차이·제목에만 있는 단어는 누락될 수 있다. 제목 임베딩 검색이므로 재판 결과·수상자 정답을 추출하지 않으며 관련·예상 보도가 상위일 수 있다.
